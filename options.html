Automatic browsing scans

Scan and save pages as you browse, without opening the inspector. Enable separately for each website. A save folder with write access is required. Browser site access is requested only when you enable this mode.

    Toolbar badges: SCAN = scanning, OK = saved, Q = queued, P = paused, SKIP = excluded, ! = failed. Keep Settings open if folder access expires when it closes. Disabling a site stops future scans; saved files and queued reports remain.

    Coverage and scan controls

    Route values affect hashed identity, not exported text. Changing identity creates new records; old records remain.

    Exclusions apply to all sites, manual scans, browsing scans, and queued retries. Existing files and queued reports remain.

    Save recovery queue

    Failed saves retain content-free JSON locally, including pagePath. The latest report for each filename is kept, up to 100 reports or 20 MB. Automatic retries run about once a minute when not paused.

    Folder-save submissions also preserve distinct evidence snapshots locally, independently of the latest-report queue and Remember history. This preservation store is limited to 100 snapshots or 20 MB and stops accepting new snapshots visibly when full. Deleting queued reports does not delete preserved evidence.

    Archiving writes immutable snapshots under access-lens-history in the selected folder, verifies each saved copy, then releases its local staging space. Archived files are retained. Existing conflicting files are never replaced. After archiving, the JSON export above includes only snapshots still staged locally.

    Exports all locally preserved snapshots without deleting them. Legacy snapshots may contain image alternative text. Save the download securely; a download request does not confirm archival completion.

      Automated keyboard testing

      Keyboard testing is off by default. Complete these steps before your first test:

      1. Click Enable keyboard testing below and check that the status says testing is enabled.
      2. If the browser disabled Access Lens after an update, open its Extensions page, review the requested permissions, and re-enable the extension. Keyboard testing requires the debugger permission included with installation.
      3. Close DevTools and other debuggers. Return to the webpage, refresh it if the extension was updated or reloaded, and open Access Lens.
      4. Choose View → Keyboard test, set the steps, and click Run keyboard test.
      5. Wait for the browser's debugging banner, leave it open, then click Begin traversal in the webpage. Canceling the banner stops the test. Keep the tab active and avoid typing until the run ends.

      Tests send Tab and Shift+Tab to move focus; they do not activate controls. Press Escape or click Stop keyboard test to interrupt a run.

      The latest structural keyboard transcript is stored locally for recovery, including interrupted runs. It contains no page text, names, typed values, or screenshots. Export JSON to keep it with a scan.

      Scan comparison and manual testing

      Off by default. When enabled, stores the latest issue baseline and manual checklist for each page state locally. No page text or addresses are stored. Disabling clears this history.
