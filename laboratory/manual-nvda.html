Manual protocol: NVDA with Chrome or Edge

Use actual NVDA speech and keyboard interaction. A successful Playwright assertion does not record a human screen-reader result. Each browser/version combination needs its own review.

Prepare and record the environment

  1. Start NVDA and open the local fixture in Chrome or Edge.
  2. Record the Windows, browser, NVDA and scanner versions, keyboard layout, relevant NVDA settings, fixture version, case ID, reviewer attribution and review time.
  3. Use Tab and Shift+Tab for focus traversal. NVDA can switch between browse and focus modes as controls receive focus; NVDA+Space toggles those modes when needed. Record any explicit mode changes.
  4. Reload between scenarios. Never treat a browser automation result as a spoken-output observation.

Keyboard-mode reference: NV Access user guide: Browse Mode. Follow the guide matching the installed NVDA version; this protocol does not prescribe a release.

Status announcements

  1. Open the announced or unannounced status fixture and wait for initial reading to finish.
  2. Tab to Complete task, then activate it with Enter or Space. Do not move focus to read the status manually.
  3. Record whether Task completed is announced and whether focus stays on the trigger. Record delayed, repeated or missing speech, rather than assuming particular timing.
  4. Reload and repeat. The negative fixture lacks status/live-region semantics; the positive example has a status region present before the update. Record actual behavior even when it differs from the known fixture condition.

Dialog focus

  1. Tab to Open trail dialog and activate it. Record the announced role/name and initial focused control.
  2. For the managed dialog, verify that the Trail name field receives focus. Traverse forward and backward; verify the background cannot receive focus while it is modal.
  3. Use Escape, then reopen and use Close dialog. Check that focus returns to the opening button after each close.
  4. For the negative fixture, observe that focus remains on the opening button outside the displayed modal. Record the impact. Escape, Close dialog, or reload resets it; there is no intentional keyboard trap.

Keyboard action

  1. Navigate from the page's Return link using Tab. Record whether Choose trail is reached and announced as a control.
  2. Use Enter and Space separately, reloading between trials. Record whether Trail selected appears after keyboard activation.
  3. The native button is the positive example. The pointer-only div is deliberately absent from sequential focus; clicking it is not a substitute for keyboard operability.

Record evidence

Download the blank manual review template. Fill only observations from an actual review. Leave unperformed checks not-tested, and include uncertainty. Keep records local and omit sensitive data. Names are self-declared attribution, not authenticated identity. The dashboard's automated run file does not import or certify these manual records.
